1. Producatori

Tinem legatura cu producatori unul si unul, adevarati maestrii in arta ciocolatii!

Acestia pot fi vazuti in pagina Producatori
Aici puteti:

  • Adauga (Create)
  • Vizualiza (Read)
  • Modifica (Update)
  • Sterge (Delete)

Nu se pot sterge producatori care au produse. Un distribuitor se poate sterge doar daca nu are produse asociate.

2. Produse

Va punem la dispozitie o gama de produse pentru cele mai capricioase gusturi!

Acestea pot fi vazuti in pagina Produse
La fel ca si pentru producatori, angajatii nostrii pot actualiza lista. Ei pot:

  • Adauga (Create)
  • Vizualiza (Read)
  • Modifica (Update)
  • Sterge (Delete)

Pagina este una interna si are ca scop gestiunea utilizatorilor.

Urmeaza:

  • REST-API pentru produse si pentru producatori
  • autentificare + roluri utilizator + continut specific rolului
  • comenzi de la noi catre producatori
  • comenzi de la clienti catre pentru noi
  • extindere baza de date - tabele pentru utilizatori si pentru comenzi
  • ... si vom mai vedea pe parcurs ...

Dupa implementarea functionalitatii de Log In, functionalitatile de actualizare a listei de produse si producatori vor fi disponibile doar angajatilor nostrii. Clientii nostrii vor putea doar sa vada aceasta pagina.

Aplicatia acopera o varietate destul de mare de notiuni referitoare la Pyuthon + Flask, HTML, CSS si chiar JavaScript. Toate sunt combinate pentru a oferi o pagina cu aspect placut, si cat mai usor si intuitiv de utilizat.
Am enumerat ce poate fi observat din punct de vedere tehnic in cod.

Python & Flask

  1. aplicatie flask
    1. entry point aplicatie - (main-ul): director 'chocodist' - prin fisierul __init__.py din acest director
    2. start aplicatie

      - cd director care contine chocodist
      - pornire venv: source .venv/bin/activate
      - pornire aplicatie: flask --app chocodist run --reload (reload - util la dezvoltare - se reporneste automat la fiecare modificare si salvare de fisiere python) sau gunicorn chocodist:app -b 127.0.0.1:8001

    3. fisier de configurare in afara directorului chocodist - config.py din directorul care contine chocodist
    4. utilizare factory method pentru a crea aplicatia
    5. instantiere extensii Bootstrap si baza de date - 'db' (in afara factory method) si inregistrare cu alicatia in factory method.
    6. pregatire utilizare extensii mail si moment
    7. Structura cod pentru a permite extinderea
      • utilizare blueprint - deocamdata doar main, dar pe acelasi model se pot adauga blueprint-uri pentru alte parti ale aplicatiei - de exemplu pentru autentificare si pentru rest-api
      • director static pentru resursele statice - imagini, script-uri
      • director template pentru template-urile html - poate fi structurat pe subdirectoare specifice pe blueprint (pentru main si template-urile de eroare nu am creat subdirector)
      • utilizare TEMPLATE-uri si biblioteca JINJA pentru a genera dinamic paginile HTML
        • template - structura HTML + locuri marcate special {{...}} {% ... %;} unde se va adauga continut dinamic
        • definire sablon general pagina - base.html si extinderea acestuia in celelalte pagini html
        • marcare zone pagina cu {% block <nume bloc> %} si extindere / sprascriere blocul in alte fisiere (ex. blocurile declarate in base.html sunt utilizate in index.html si alte fisiere care extind base.html) (cod HTML caractere speciale)
    8. utilizare blueprint pentru a structura aplicatia
    9. Implementare comenzi CLI ale aplicatiei: vizibile cu: flask --app chocodist --help
    10. Personalizare shell - fac disponibile in shell obiectu baza de date: 'db' si modelele - clasele prin care accesez tabelele din baza de date
    11. Tratare personalizata erori - pagini de eroare definite pentru diverse tipuri de erori
    12. Structurare aplicatie pe arhitectura Model-View-Controler
      • Model - date - baza de date si functiile de interactiune cu aceasta.
      • View - fisiere view per blueprint, rute + functii view de tratare a cererilor
      • Controller - procesare specifica - pentru a pastra modelele si functiile view compacte
    13. end point - identificator pentru a asocia un URL la o functie view - folosit in url_for("blueprint.nume_functie_view")
      detalii endpoint pe stackoverflow
    14. formulare flask - bibliotecat Flask-WTF (what-the-form) - main/forms.py
      • Campuri specifice StringField, IntegerField, SelectField, HiddenField etc.
        documentatie Flask WTF campuri, validatori
      • Utilizare validatori - validare elemente formular - vezi link-ul de mai sus
      • Securizare cu CSRF protection documentatie WTF CSRF
    15. Formular definit explicit - in HTML - pentru adaugare produse - ofera flexibilitate dar este mai mult de lucru.
  2. Sqlalchemy si ORM penru date
    1. utilizare biblioteca sqlalchemy pentru lucru cu baza de date
    2. utilizare ORM (Object Relational Model) adica obiecte pentru tabelele din baza de date si interactiunea cu baza de date prin aceste obiecte - functionalitate pusa la dispozitie de sqlalchemy
    3. interogari SQL folosind obiectele, nu construite direct in SQL - interogarile SQL generate sunt afisate in loguri
    4. interogari cu join, where, order_by, having, external left join, etc.
    5. relatii intre obiecte - apar in obiecte dar nu si in tabele - in tabele am doar foreign-key (ex id_producator in tabela produse), in obiecte am si numele producatorului, iar in producatori, lista de produse
    6. constrangeri unicitate - pe anumite campuri
    7. nu am activat optiunea de stergere in cascada - nu pot sterge un producator care are produse asociate cu el
  3. logging

CSS

  1. fisier style.css in directorul static (ghid utilicare css de la MDN Mozilla Developer Network)
    1. identificare dupa id element: #id: ex: #page_content
    2. -- nu am facut identificat dupa tag - este prea generica si nu ajuta
    3. identificare dupa clasa: .nume_clasa
    4. identificare dupa pseudoclase: ex: td:hover
    5. utilizare combinatori: descendenta: identificator_1 identificator_2 am elementul 2 in elementul 1 - nu neaparat direct
    6. utilizare combinator de descendeta + next sibling pentru identificare: identificator_1 identificator_2 + identificator 3
    7. utilizare combinator child: identificator 1 > identificator_2
    8. utilizare atribute element pentru identificare: ex: div[class="nume clasa"]
